# Code Review

## 목적

FE와 BE 개발이 끝난 코드에 대해 직관성, 보안 취약성, 재사용성을 중심으로 리뷰하고, 사용자가 바로 판단할 수 있도록 한글 표로 결과를 제시한다.

## 호출 조건

이 스킬은 사용자가 명시적으로 `$code-review`를 호출하거나, 코드 리뷰를 해 달라고 명확히 요청한 경우에만 사용한다. 일반적인 구현, 디버깅, 리팩터링, 설명 요청에는 이 스킬을 적용하지 않는다.

## 리뷰 범위

- FE: React, TypeScript, Vite 기반 코드
- BE: Python, FastAPI 기반 코드
- 공통: 설정, 의존성, 테스트, 빌드 스크립트, API 계약, 에러 처리, 인증/인가 흐름

## 작업 절차

1. 리뷰 대상 범위를 확인한다. 사용자가 범위를 지정하지 않으면 최근 변경 파일, 현재 작업 브랜치의 diff, 또는 관련 FE/BE 디렉터리를 우선 검토한다.
2. 프로젝트 구조와 실행 명령을 확인한다. `package.json`, `pyproject.toml`, `requirements.txt`, 테스트/린트 설정을 먼저 읽는다.
3. 가능한 경우 정적 검사, 타입 검사, 테스트를 실행한다. 실행하지 못한 검사는 결과 표나 검증 메모에 이유를 명확히 적는다.
4. 발견 사항은 영향도와 재현 가능성을 기준으로 정리한다. 추측은 추측이라고 표시하고, 실제 코드 위치를 근거로 든다.
5. 최종 답변은 반드시 한글로 작성하고, 핵심 리뷰 결과를 표 형식으로 먼저 제시한다.

## 리뷰 기준

### 코드의 직관성

- 함수, 컴포넌트, 모듈의 책임이 한눈에 드러나는지 확인한다.
- 이름, 분기, 상태 관리, 의존성 흐름이 읽기 쉬운지 확인한다.
- FastAPI 라우터, 서비스, 스키마, 의존성 주입이 과도하게 섞이지 않았는지 확인한다.
- React 컴포넌트, 훅, API 클라이언트, 상태 관리 코드의 역할이 분리되어 있는지 확인한다.

### 보안 취약성

- 인증, 인가, 세션, 토큰, CORS, 입력 검증, 파일 업로드, 에러 노출을 확인한다.
- FastAPI에서 Pydantic 검증, 의존성 기반 권한 확인, 예외 처리, 비밀 값 관리가 적절한지 확인한다.
- React에서 민감 정보 노출, XSS 위험, 위험한 HTML 삽입, 클라이언트 전용 권한 판단을 확인한다.
- SQL/ORM 쿼리, 외부 요청, 경로 처리, 환경 변수 사용에서 주입이나 정보 노출 위험을 확인한다.

### 재사용성

- 중복 로직, 반복되는 API 호출 패턴, 공통 유틸/훅/서비스로 분리할 수 있는 부분을 확인한다.
- 추상화가 과하거나 실제 중복을 줄이지 못하는지 함께 평가한다.
- 타입, 스키마, DTO, API 응답 구조가 FE/BE 간 일관되게 재사용되는지 확인한다.
- 테스트하기 어려운 결합이나 전역 상태 의존성을 확인한다.

## 결과 형식

최종 답변의 첫 번째 주요 섹션에 다음 표를 포함한다.

| 영역 | 심각도 | 파일/위치 | 리뷰 기준 | 발견 내용 | 권장 조치 |
| --- | --- | --- | --- | --- | --- |
| FE 또는 BE 또는 공통 | 높음/중간/낮음 | 파일 경로:라인 | 직관성/보안/재사용성 | 근거 중심 설명 | 구체적 수정 방향 |

표 작성 규칙:

- 심각도는 `높음`, `중간`, `낮음` 중 하나로 표시한다.
- 파일/위치는 가능한 한 `path/to/file:line` 형식으로 쓴다.
- 보안 취약성은 실제 악용 가능성, 필요한 조건, 영향 범위를 함께 적는다.
- 문제가 없으면 표에 `특이사항 없음`을 명시하고, 확인한 범위를 적는다.
- 표 아래에는 `검증`, `남은 리스크`를 짧게 덧붙인다.

## 답변 원칙

- 한글로 간결하고 직접적으로 작성한다.
- 발견 사항을 우선순위순으로 제시한다.
- 코드 변경을 직접 수행하지 말고 리뷰 결과와 권장 조치에 집중한다. 사용자가 수정까지 요청하면 그때 별도 작업으로 진행한다.
- 스타일 취향만의 지적은 피하고, 유지보수성, 보안, 결함 가능성에 연결되는 내용만 포함한다.
